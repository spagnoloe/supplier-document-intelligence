# Write-up: supplier document intelligence

**Architecture.** One LangGraph graph per Source: **load** (by file type) → **extract** (Gemini, structured output into one Pydantic schema) → **validate** (deterministic checks) → **second read** (conditional) → **store** (SQLite). After the batch, **reconcile** links Sources of one Quotation and records Conflicts and Price comparisons. A Streamlit UI and `sdi export` sit on a read model. [ADRs](adr/): no per-supplier logic (0001); the model extracts only stated values, code derives the rest (0002); a *Conflict* (copies of one Quotation disagree) ≠ a *Price comparison* (suppliers quoting one Product) (0003); review comes from per-field verification, not self-confidence (0004); Gemini free tier (0005).

**Extensibility.** *New supplier or layout* (unseen JSON field names, a new PDF layout, a new customer system's export): zero code changes. Loaders handle format; one generic prompt (no supplier names, layouts or examples) handles meaning. *New file type*: one loader module plus one import line in `src/sdi/loaders/__init__.py`. The Excel loader proves it: [commit `51f20e9`](https://github.com/spagnoloe/supplier-document-intelligence/commit/51f20e9) changed no other module, and its six lines matched the PDF they were copied from. Unknown types fail loudly, for that Source only. *Same product from two systems*: `src/sdi/reconcile/` links Sources by normalized supplier + quote reference and matches lines by Product key (INNs + strengths + dosage form). Disagreements become Conflicts shown side by side and sent to review; nothing is auto-merged.

**Framework.** LangGraph + LangChain. *What it bought:* nodes per step with a conditional edge for the second read; a `RetryPolicy` scoped to structured-output errors; `graph.batch` with a concurrency limit and per-Source failure isolation; `with_structured_output` + Pydantic; and LangChain's SQLite LLM cache, which makes the eval reproducible at zero cost. *What it cost:* state boilerplate for a mostly linear flow, and leaks. The cache stores responses before parsing, so a retry replayed the same malformed answer until retries got their own seeds. A same-model second read hit the first read's cache entry. Gemini's structured output can't express open-ended dict keys, so evidence became a list. LangSmith tracing is available via env vars but wasn't used.

**Email and images vs structured Sources.** All go through the same prompt; what differs is how values get verified. *Text* (JSON, PDF, email, Excel): every value carries a verbatim evidence span that code finds in the text and checks the value against. *Email:* headers plus the plain-text body. The prompt asks for final values after corrections, with the revision in `revision_note`, which forces review (the P.S. price correction is caught). *Images:* direct vision, no OCR. Unreadable values must come back `null`, never guessed. There's no text to check spans against, so verification relies on arithmetic (unit × pack, qty × price × (1 − discount) = total), the value against its own span, and a second read. An unverified critical field on an image keeps the line in review.

**Uncertainty.** Each field is `verified`, `unverified` or `failed`, with stable reason codes (`ARITHMETIC_MISMATCH`, `SECOND_READ_DISAGREEMENT`, …). A line is `needs_review` when a critical field fails, or is unverified on an image, or the line is in a Conflict or was revised. Missing FX rates leave USD empty (`FX_UNAVAILABLE`) and are never estimated. **Eval** (hand-labelled gold set, 9 Sources, [results](../eval/results.md)): 43/43 lines found, 0 extra. Field accuracy is 97% (100% on JSON, email and Excel, 98% PDF, 89% images). 10 of 17 wrong fields were flagged (9/15 on images). Review load: 47% of lines, 15% of fields; 10% of correct fields were flagged. The 7 unflagged errors are mostly non-critical fields on the glare scan (discount, a line total, the quote reference) and one PDF dosage-form wording.

**Production readiness.** *Cost:* flash-lite per Source, a second read only when needed; for large sheets, an LLM-proposed column mapping cached per structure fingerprint instead of whole-table prompts. *Latency:* queue-fed workers per Source, rate-limited per provider. *Monitoring:* tracing; reason-code rates, review load and correction rate per supplier as drift alarms; reviewer corrections fed back into the gold set. *PII and regulated data:* the free tier may train on inputs, which is unacceptable for real supplier data. Use a no-training paid tier with data residency and a DPA, redact personal data from emails, encrypt Sources at rest. *Review UX:* FastAPI plus a real frontend with authentication instead of a typed name, the document beside the line with evidence spans highlighted, and earlier decisions offered as suggestions on a re-read. *Models:* provider-agnostic, with fallbacks and a cross-family second read.

**CI/CD and infrastructure.** CI: ruff, mypy, pytest (no model calls), and `sdi eval --cached-only` with a score threshold as a regression gate. A live eval runs on any prompt, schema or model change, which the extraction fingerprint already detects. Deploy as a containerized worker plus API, with Postgres instead of SQLite and Sources in object storage. Scale horizontally behind a queue; the content fingerprint keeps re-deliveries idempotent.

**Limitations.** Alternative offers in notes aren't extracted. Tables are serialized whole into the prompt. No OCR confidence: second-read disagreement stands in for it. The second read uses a single provider, so its misreads are correlated (the committed eval even used one model for both, because of quota). Price comparison requires an exact dosage-form match, so "Oral suspension powder" and "Powder for oral suspension" don't group. Re-reading a Source restarts its review. A PDF that mixes text and scanned pages is read as text. Salt words are stripped from a fixed list. Non-ECB currencies get no USD price. Misread non-critical image fields can pass.

**The suggested data model.** One flat record per product can't hold a real quotation. It lacks a supplier, quote reference and date, so copies can't be linked; it lacks Incoterm and validity, so prices aren't comparable; and it lacks pack size, UOM, tiers and discounts. A single `inn` string can't represent combinations (TLD, HRZE) or tell salts apart from the moiety. Without strength and dosage form, a salbutamol inhaler and a syrup look like one product. `price_per_uom` forces the model to do arithmetic on per-box quotes. Nothing records certainty or provenance. **Improved:** a Quotation header with terms plus a list of lines; `active_ingredients[]` (INN + strength); dosage form; stated Unit *and* Pack price with code-derived values and FX provenance; tiers and discount; and per-field evidence, verification and Review reasons with a Source + line pointer. Still missing: manufacturer vs supplier, WHO-PQ/SRA status, shelf life, lead time, MOQ, product IDs (GTIN, ATC).

*Assumptions:* `price_per_uom` means the stated Unit price before discount, at the lowest-volume tier, in USD at the ECB rate on the issue date. INN means the WHO INN of the active moiety. A line quantity may count UOMs or Packs.
